# 시연 전 최종 리허설 체크리스트

이번 세션에서만 이런 패치가 들어감: 장학금 매칭(전공명 강제포함) 버그 수정, 지역 필터 보강,
상담단계 할루시네이션 수정, 말투/마크다운 통일, 학번 기반 신청 조회, 반려/승인 즉시 이메일
알림, staff.html 이메일 표시, 반려→재제출 개인정보 자동 재사용. 패치가 많이 쌓였으니
`python3 app.py`로 로컬 실서버 띄워서 아래 순서대로 육안 확인 권장.

## 1. 장학금 매칭 (시나리오 1)
- [ ] 시각디자인 전공 + 인천 미추홀구 학생으로 다시 물어봐서, 저번에 안 걸러지던 장학금이 이제 뜨는지
- [ ] "모름, 다자녀야" 같은 애매한 답변에도 `condition_check` 단계가 실제 후보 조건을 하나하나 짚어 물어보는지 (문구가 자연스러운지 — 이 부분은 로컬 Gemini 응답으로만 확인 가능)
- [ ] 후보 제시 후 번호 대신 반박("아니 그거 아니야") 해도 무한루프 없이 자연스럽게 반응하는지
- [ ] "1번은 얼마 주는거야?" 같은 상담 질문에 다른 후보 정보가 섞여서 할루시네이션 안 나는지
- [ ] 전체 대화에서 마크다운(별표 등) 안 섞이고, 반말/존댓말 안 섞이는지

## 2. 복수전공 인정신청 (시나리오 2)
- [ ] 미래자동차공학과 → 컴퓨터공학전공 조합으로 처음부터 끝까지 새로 신청서 제출
- [ ] 마지막 확인 단계에서 이름/학번/학년/소속/**이메일** 다 물어보는지
- [ ] `/staff`에서 반려 처리 → 넣은 이메일로 실제 메일 오는지 (스팸함도 확인)
- [ ] 반려 후 "신청확인"이라고 학번 입력 → 반려 사유 안내 + 재제출 흐름 진입하는지
- [ ] 재제출 시 "응" 답하면 이름/학번/학년/소속/이메일 다시 안 물어보고 바로 확인 문구(`저번에 낸 신청서에 있던 개인정보 그대로 이어서 쓸게!`)로 넘어가는지
- [ ] 재제출 후 3단계(학과장→복수전공학과장→행정처) 전부 승인 → 최종 승인 이메일 오는지
- [ ] staff.html 카드에 학생 이메일이 보이고, 승인/반려 버튼 아래 "이메일 자동 발송" 안내 문구가 상황(반려 즉시 / 마지막 단계 승인)에 맞게 뜨는지

## 3. 통합 흐름
- [ ] 장학금 상담 중간에 "복수전공 되나요?" 물어보면 자연스럽게 전환되고, 다시 장학금으로 돌아와도 진행상황 안 날아가는지
- [ ] 첫 인사말이 모호할 때(예: "안녕") 추측 안 하고 되물어보는지

## 4. 환경/배포
- [ ] Render 환경변수에 `RESEND_API_KEY` 실제로 들어있는지 (config.json엔 없는 게 정상)
- [ ] git push 최신 상태인지, Render 재배포 로그에 에러 없는지
- [ ] `/admin`에서 Gemini 키/모델 정상 조회되는지

## 우선순위 참고
- 1~2번(핵심 두 시나리오)이 청중이 직접 만져볼 부분이라 가장 중요
- 3번은 통합 UX 매끄러움 확인용
- 4번은 배포 환경 최종 점검 — 시연 당일 아침에 한 번 더 확인 권장
